# Architecture and Design

This document captures **high-level architecture and general design principles** only.
Detailed phase-level designs live in `docs/specs/YYYY-MM-DD-<topic>-design.md`.

## System Overview

Silver Bullet ships one source tree through three first-class host surfaces:

- **Claude Code plugin** — `.claude-plugin/` manifests, `hooks/hooks.json`, skills rendered into `agents/claude/`.
- **Codex package** — `plugins/silver-bullet/` with `.codex-plugin/plugin.json`, the native `skill-source/` mirror, and hooks routed through `hooks/codex-hook-adapter.sh` by `scripts/install-codex.sh`.
- **Cursor plugin** — `.cursor-plugin/` manifests plus `plugins/silver-bullet/` with `cursor-hooks.json` (generated from `hooks/hooks.json`), the `commands/` stubs and `skill-source/`; hooks run through `hooks/cursor-hook-bridge.sh`.

All three are composed of shell hook scripts, skill markdown files, slash-command stubs, JSON configuration and workflow documentation. SB owns the lifecycle authority for default software-engineering workflows and calls optional provider, DevOps, design, research, or issue-tracker plugins only when a selected flow needs their external capability. Its enforcement layer prevents the runtime from skipping required workflow steps.

`hooks/lib/runtime-paths.sh` resolves the active runtime — `claude`, `codex`, `cursor`, `opencode`, `pi`, `goose` or `hermes` (from `SILVER_BULLET_RUNTIME` or host environment markers) — and with it the state root (`~/.claude`, `~/.codex`, `~/.cursor`, `~/.config/opencode`, `~/.pi/agent`, `~/.config/goose`, `~/.hermes`). Claude Code, Codex and Cursor are the supported plugin hosts; the other runtimes share the state layout and the five-tool stack integration. Optional extension plugins that do not publish Codex artifacts are represented by thin wrappers in the unified `alo-labs/agent-plugins` marketplace, which fetches upstream content at install time instead of vendoring it here.

No server, no database — all state lives in flat files under `${SB_RUNTIME_HOME_ROOT}/.silver-bullet/`.

## Core Components

| Component | Path | Responsibility |
|-----------|------|----------------|
| Hook scripts | `hooks/*.sh`, `hooks/session-start` | Pre/PostToolUse, Stop, SessionStart and UserPromptSubmit enforcement ([HOOKS.md](HOOKS.md)) |
| Hook libraries | `hooks/lib/` | Runtime paths, payload parsing, project activation, gate modules |
| Skill files | `skills/*/SKILL.md` | Declarative workflow instructions loaded through the active host's supported skill channel |
| Rendered skill bundles | `agents/claude/`, `host-bundles/{codex,cursor}/`, `plugins/silver-bullet/skill-source/` | Per-host renderings of `skills/`, generated by `scripts/sync-codex-package.sh` |
| Workflow docs | `docs/workflows/` | Full per-session step-by-step procedures (active copies) |
| APO catalog | `docs/apo-catalog.json` | Atomic flows, workflows, flow steps and V-loops; generated views under `docs/` |
| Commands | `plugins/silver-bullet/commands/` | `/sb:*` slash-command stubs for the Cursor package surface; Codex uses the native skill-source mirror |
| Templates | `templates/` | Bootstrap files copied during `/sb:init` setup |
| Installers | `scripts/install-claude.sh`, `scripts/install-codex.sh`, `scripts/install-cursor.sh` | Register the marketplaces, merge hooks and bootstrap dependencies per host |
| Runtime CLI | `scripts/silver-bullet` | `silver-bullet invoke-skill` adapter for hosts without a recordable Skill tool |
| Unified agent marketplace | `https://github.com/alo-labs/agent-plugins` | Thin tri-host manifests; Codex entries fetch upstream at install time |
| Live runtime matrix | `tests/live/`, `tests/e2e-live/` | Live harnesses with runtime adapters (Claude by default) |
| Config | `.silver-bullet.json` | Project-level settings and required/tracked skill lists ([CONFIGURATION.md](CONFIGURATION.md)) |
| State file | `${SB_RUNTIME_HOME_ROOT}/.silver-bullet/state` | Flat file recording invoked skills, scoped to branch and worktree |
| Trivial flag | `${SB_RUNTIME_HOME_ROOT}/.silver-bullet/trivial` | Legacy compatibility marker. Agents route trivial work through `/sb:fast`; `trivial-file-guard.sh` blocks creating the marker |

### Key hooks

| Hook | Trigger | Behavior |
|------|---------|----------|
| `record-skill.sh` | PostToolUse (Skill tool calls; Codex SB adapter receipts) | Appends normalized skill name to state file |
| `record-requested-skill.sh` | UserPromptSubmit | Records requested SB route markers before the next turn starts |
| `dev-cycle-check.sh` | Pre+PostToolUse (Edit/Write/MultiEdit/`apply_patch`, shell) | 4-stage gate: blocks source edits if planning incomplete |
| `compliance-status.sh` | PostToolUse (all tools) | Emits live progress per tool call |
| `completion-audit.sh` | Pre+PostToolUse (shell) | Two-tier: blocks `git commit/push` if `required_planning` skills are missing; blocks `gh pr create/merge`, deploy and `gh release create` if the full `required_deploy` list (plus release gates) is missing |
| `planning-file-guard.sh` | PreToolUse (Edit/Write/MultiEdit/`apply_patch`) | Blocks direct edits to guarded planning artifacts (ROADMAP.md, STATE.md, etc.); requires the owning SB workflow path instead |
| `ci-status-check.sh` | Pre+PostToolUse (shell) | Blocks push, PR create/merge and release while the latest CI run failed; warns after a commit |
| `prompt-reminder.sh` | UserPromptSubmit | Re-injects missing skills list before every user message and surfaces current workflow context |
| `stop-check.sh` | Stop / SubagentStop | Requires `required_planning` skills (planning floor) before session ends. Full `required_deploy` is enforced by `completion-audit.sh` at delivery commands |
| `session-start` | SessionStart | Injects core rules, resets branch-scoped state, deletes any stale trivial marker (never creates it) |
| `trivial-file-clear.sh` | PostToolUse (Write/Edit/MultiEdit/`apply_patch`) | Clears the trivial marker when files are modified |

[HOOKS.md](HOOKS.md) lists all registered hooks.

### Fast Path

Silver Bullet routes trivial changes through `/sb:fast`, which classifies the change
and dispatches to SB's fast path without the full workflow overhead. The legacy touch-file
marker remains only as a compatibility detail for older sessions, not as a supported
entry point.

## Design Principles

1. **Never modify third-party plugins.** All enforcement is additive to the host project.
2. **12 layers, no single bypass.** Enforcement survives context window resets because hooks
   re-fire on every tool call, not just at session start ([ENFORCEMENT.md](ENFORCEMENT.md)).
3. **User instructions always take precedence.** Any existing project instruction file (`CLAUDE.md` / `AGENTS.md`) overrides SB defaults, but SB does not require one to exist.
4. **Non-destructive file operations.** Hooks write only SB state and SB-owned artifacts
   (session logs, phase archives, the PR traceability block). Setup commands create new files;
   update mode overwrites only `silver-bullet.md`.
5. **Flat-file state.** No process, no daemon, no server. State is a text file. Any tool that
   writes to it or reads from it can be independently audited.
6. **Template parity.** `templates/workflows/` must remain byte-identical to `docs/workflows/`
   so new projects get the same enforcement rules as the current project.
7. **Packaging boundaries.** SB-owned plugin bundles never vendor optional extension plugins or
   project instance artifacts. The Codex bundle stays SB-only; non-native Codex support for
   external extensions lives in the shared marketplace.

### Packaging Boundaries

- `/.planning/` and `/.claude/` are project-instance artifacts, not plugin content.
- `silver-bullet.md` is the project copy; `templates/silver-bullet.md.base` is the source template.
- `plugins/silver-bullet/` is a curated package surface, not a mirror of the whole repository: root docs, `docs/`, `hooks/` and `scripts/` are symlinks; `skill-source/`, `templates/` and `cursor-hooks.json` are generated.
- `plugins/silver-bullet/commands/` ships inside the shared package for Cursor's command surface; the Codex manifest intentionally omits `commands` so Codex does not migrate stubs into `source-command-*` skills.
- Third-party Codex wrappers for optional extensions belong in the shared marketplace and fetch upstream content at install time.

## Technology Choices

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Language | Bash, plus Python 3 helpers | Hooks and scripts are Bash with `jq` for JSON; small Python 3 helpers parse tool payloads, and generators/validators are Python. Core hooks need no Node.js runtime; Node is used only by opt-in tools (Context Mode, agentmemory, Alumnium) |
| Config format | JSON | Machine-readable by hooks and CI; human-readable for customization |
| Skill format | Markdown | Loaded through the active host's skill surface; Codex mirrors SB skills into the native `/sb:` picker and records via the SB adapter |
| State format | Line-delimited text | `grep -q` lookups; append-only; trivially auditable |
| CI | GitHub Actions | Target audience is GitHub repos; `gh` CLI integrates release workflow ([CICD.md](CICD.md)) |
| Codex packaging | Thin wrapper + install-time fetch | Keeps SB bundle SB-only while supporting third-party plugins that lack native Codex packaging |
