# Project Knowledge — 2026-05

## Architecture Patterns

2026-05-19 — Silver Bullet's session log now carries a live nested intent ledger. The request recorder appends active branches as they are intercepted, and the completion recorder marks them done even when the underlying state already contained the skill marker.

2026-05-14 — Silver Bullet should compose around GSD rather than mirror it. GSD owns project lifecycle artifacts and execution state; SB owns dynamic workflow composition, precondition checks, dependency orchestration, and final-delivery enforcement.

2026-05-07 — Silver Bullet's Codex package stays SB-only. First-party dependencies are installed from their official source repos, and third-party plugins without native Codex packaging are represented by thin wrappers in the shared marketplace that fetch upstream content at install time. The marketplace is a registry, not a mirror.

2026-05-07 — The shared live matrix uses one scenario suite with runtime adapters. Claude and Codex execute the same scenario bodies, but the harness selects the CLI/bootstrap path at the edge and keeps the adapters separate from the scenario logic.

2026-05-08 — Treat documentation governance as a versioned contract (`docs/doc-scheme.json`) with a human policy companion (`docs/doc-scheme.md`). Hooks should enforce only the contract and emit actionable remediation payloads consumed by a single docs authority skill.

## Known Gotchas

2026-05-19 — A request recorder that only writes the requested-state sidecar can make the workflow look healthy while leaving the human-readable session log stale. The active ledger and completion state need to be updated together.

2026-05-14 — Requested routes are not completed skills. UserPromptSubmit should write request intent to a requested-state sidecar, while Skill/PostToolUse writes completed markers only after an actual skill invocation.

2026-05-14 — Read-only shell commands can contain skill names as search strings. Hook checks that enforce route floors must inspect the invoked command token, not arbitrary command arguments or heredoc bodies.

2026-05-07 — Parallel Claude and Codex live runs can contaminate each other's state because both runtimes touch the same Silver Bullet state path under `${SB_RUNTIME_HOME_ROOT}/.silver-bullet/`. The matrix must be serialized when both runtimes are exercised in the same session.

2026-05-07 — Project-instance artifacts such as `/.planning/`, `/.claude/`, and `/.forge/` must stay out of plugin bundles. The SB Codex package and the shared marketplace are curated surfaces, not a repo mirror.

2026-05-08 — Doc-scheme gate tests can false-fail if deprecated global CI bypass artifacts (`${SB_RUNTIME_HOME_ROOT}/.silver-bullet/trivial`, `ci-red-override`) leak into test runs. Integration and hook tests now clear these files in setup/teardown to keep CI behavior deterministic.

2026-05-08 — If checklist granularity is missing, docs enforcement can silently drift. The checklist now requires explicit numeric `task_granularity`, and hooks enforce only configured levels (2/3) from the scheme contract.

## Key Decisions

2026-05-19 — The session log is part of the authoritative orchestration trail. Silver Bullet now keeps the `## Active Intent Ledger` section in sync with request and completion hooks so multi-turn work does not lose branches.

2026-05-14 — Implementation edits unlock after the selected SB+GSD pre-execution chain completes. Code review, security, validation, verification, and ship markers remain final-delivery gates and are backed by artifact checks.

2026-05-14 — Plugin-runtime live matrix and 4-stage pre-release gates are release-profile features. The Silver Bullet plugin repo opts into them, while downstream projects stay on the generic release profile unless configured otherwise.

2026-05-07 — Keep Claude packaging intact while moving Codex packaging into a shared marketplace and preserving only thin wrapper metadata in the marketplace for third-party plugins that lack native Codex packages.

2026-05-07 — Release validation for multi-runtime support must prove both runtimes, not just one. The shared live matrix is now part of release confidence, not a separate nice-to-have.

2026-05-08 — Doc completion/delivery gates now derive governed-doc coverage from the live docs inventory: every concrete doc file under `docs/` (except monthly knowledge/lessons files covered by wildcard keys), plus root docs when present. Missing checklist keys now hard-block completion and delivery.

2026-05-08 — `/silver:init` no longer performs direct docs migration/scaffolding. It delegates docs bootstrap/reconciliation to `/silver:ensure-docs`, making one skill the authority for greenfield scaffolding, brownfield mapping, and hook-gap remediation.

## Recurring Patterns

2026-05-14 — When a wrapper skill delegates to another framework, expose the wrapper as the public SB route and keep the dependency detail inside that wrapper. This prevents users and docs from treating the dependency as the primary orchestrator.

2026-05-07 — When a project supports multiple coding runtimes, duplicate only the transport/bootstrap layer. Keep scenario bodies, assertions, and fixtures shared so behavior stays comparable across runtimes.

2026-05-08 — For policy-heavy hooks, pair enforcement changes with deterministic test-environment cleanup so legacy machine-local artifacts cannot shadow intended gate behavior.

2026-05-08 — Brownfield doc standardization is safest when "switch to canonical docs" moves prior artifacts into `docs/archive/<timestamp>/...` and records every move in a machine-readable manifest.

2026-05-10 — When a canonical docs contract exists, neighboring scheme pages should become short compatibility pointers rather than parallel policy copies. That keeps the live surface small and makes the authoritative path obvious.
