# Project Knowledge — 2026-10

## Architecture Patterns

2026-10-17 — The hook surface is large (dozens of scripts on seven events), so hand-written hook lists drift. `docs/HOOKS.md` is generated from `hooks/hooks.json` by `scripts/generate-hook-reference.py`; the curated purposes live in `docs/hooks-purpose.json` (outside `scripts/`, because `validate-host-agnostic-core.sh` rejects host names in shared scripts), and `tests/docs/test-hook-reference.sh` fails when a registered hook has no purpose or the page is stale.

## Known Gotchas

2026-10-17 — Missing `jq` does not make every hook fail open: the core gates block in an initiated project (`hooks/lib/jq-gate.sh`), and `completion-audit.sh` blocks delivery commands even outside a project.

2026-10-17 — The enterprise policy delivery block applies by default: with no `enterprise_policy` profile, `production_deploy_requires_human` defaults to true, so PRs, releases and deploys need the human approval marker in the runtime state dir.

2026-10-17 — `scripts/apply-site-chrome.py` has no `--help`; running it rewrites site pages in place.

## Key Decisions

2026-10-17 — Counts stated in README/AGENTS (skills, command stubs, catalog sizes) are checked against their sources by `tests/docs/test-doc-facts.sh`, which also keeps `scripts/README.md` complete and `docs/doc-scheme.md` identical to its template.

2026-10-17 — The three GSD comparison pages were merged into `docs/sb-vs-gsd.md`; the CI/CD reference moved from `docs/internal/` to `docs/CICD.md`, the name the doc scheme prescribes.

## Recurring Patterns

2026-10-17 — Prefer generated or test-checked documentation for anything derived from code (hook registrations, counts, script inventories) and keep prose for intent.
