# Phase 94.01 Plan: SB/GSD Alignment Cleanup

## Goal

Resolve direct and potential Silver Bullet friction against GSD lifecycle ownership so SB behaves as an Agentic Process Orchestrator around GSD instead of replacing, bypassing, or deadlocking it.

## Context

The user requested a comprehensive fix pass after a codebase audit found ordering, naming, gating, documentation, and release-surface drift between SB and GSD. This plan is intentionally scoped to alignment fixes, not unrelated feature work.

## Scope

- Hook behavior for workflow admission, planning floors, dependency checks, completion checks, and planning-file ownership.
- SB skill contracts and documentation language that mention GSD, Superpowers, MultAI, release, quality gates, or legacy workflow tracking.
- Tests covering the changed lifecycle semantics.
- Generated Codex package synchronization from canonical source files.

## Non-Goals

- Redesigning GSD.
- Replacing GSD-owned project lifecycle artifacts with SB artifacts.
- Implementing generic release matrices for every downstream project type beyond making current plugin-specific gates configurable.

## Execution Notes

- GSD remains lifecycle authority for discuss, plan, execute, verify, ship, and milestone completion.
- SB may enforce preconditions and final gates, but must not require post-execution markers before implementation edits.
- Superpowers remains a delegated dependency only where SB explicitly routes to its craft-discipline skills.

## Verification

- Run focused hook tests for every changed hook.
- Run skill-reference and router/contract tests.
- Run package sync tests after regenerating the Codex package.
- Run the full local test suite if focused suites pass.
