- Humans read a short story plus the sections that matter for *this* kind of software.

- REQUIREMENTS.md remains the **REQ/NFR ID index** (kinds may add NFR *packs* as extra rows/categories — not a third canonical doc).

## PRIMARY — SPEC.md template contract (world-class)

Canonical **core** file: [`templates/specs/SPEC.md.template`](../../../../templates/specs/SPEC.md.template). Canonical **packs:** `templates/specs/packs/<pack-id>.md` (new). Canonical **kind catalog:** `templates/specs/software-kinds.yaml` (new). Compiler concatenates core + selected packs into `.planning/SPEC.md`. Consumers never maintain a third file.

World-class means: a PM can review intent in one sitting; an engineer can implement from IDs; a model can quote MUST/MUST NOT, GWT, and error/API contracts without guessing. **Presence of a heading is a contract**, not decoration. Kind-required packs are a **heading + body + pack-local IDs** contract, not headings-only (R5b-F01).

### Dual audience (non-negotiable)

| Reader | SPEC must give them |
|--------|---------------------|
| Human (PM/eng/stakeholder) | Overview in 2–4 sentences; stories; the kind-relevant journey (UX *or* CLI *or* API *or* pipeline); AC they can demo; change history |
| Model (plan / RFL / QC / execute) | YAML keys; stable IDs; GWT; `### Invariants`; coverage join via REQUIREMENTS; no unlabeled checkboxes |

### Frontmatter (YAML) — core template
