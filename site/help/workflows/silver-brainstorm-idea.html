/silver:brainstorm-idea

Idea-stage orchestration workflow — turns raw concepts into a milestone-ready starting point by pairing PM brainstorming, engineering brainstorming, and GSD milestone capture. Use when there is no SPEC.md yet.

Overview

/silver:brainstorm-idea is Silver Bullet's entry point for concept-stage work that is not ready to become a formal SPEC.md. It orchestrates the early thinking needed to turn a raw idea into a milestone seed, but it never writes implementation directly.

Invoked directly as /silver:brainstorm-idea, or automatically by /silver when intent classification detects concept-intake signals and no SPEC.md exists. See Composable Flows for the broader orchestration model.

When to use

Entry trigger signals for /silver:brainstorm-idea:

  • "I want to build" / "I have an idea" / "here's my concept"
  • "what if we" / "thinking of" / other multi-sentence concept descriptions
  • No SPEC.md exists yet, or the user explicitly wants idea-to-milestone intake before formal spec creation
ℹ
Not a spec workflow: if the request is already formalized in SPEC.md, route to /silver:spec instead. /silver:brainstorm-idea exists for the raw concept stage.

Composition

/silver:brainstorm-idea composes the early discovery chain rather than a full implementation pipeline. Typical path: FLOW 0 (BOOTSTRAP) → FLOW 1 (ORIENT) → FLOW 3 (IDEATE). The workflow then creates a milestone anchor and hands open questions to discussion so the concept can be stabilized.

The design intent is to keep idea intake light, but not shallow: PM brainstorming captures the problem and value, engineering brainstorming turns that into a technical shape, and milestone creation makes the next phase concrete.

Workflow steps

Pre-flight

Silver Bullet reads silver-bullet.md §10 to load user workflow preferences before any step executes.

Step 1 — Product brainstorming

Invoke /product-brainstorming. Purpose: PM lens — problem definition, user value, personas, success metrics, scope boundaries.

Step 2 — Engineering brainstorming

Invoke silver:brainstorm. Purpose: translate the raw concept into an engineering shape — architecture direction, constraints, and implementation implications.

Step 3 — Milestone scaffold

Invoke gsd-new-milestone. Purpose: create the milestone anchor and project artifacts that will carry the concept forward.

Step 4 — Decision lock

Invoke gsd-discuss-phase. Purpose: resolve open questions, capture the Phase 1 context, and lock the first decisions before any deeper planning begins.

Spec handoff

⚠
Switch to /silver:spec once the concept hardens. If the user already has formal requirements, acceptance criteria, or a structured SPEC.md, idea intake is the wrong tool. Use /silver:spec for formal spec elicitation and then continue with the spec-driven workflow.

Example invocation

/silver:brainstorm-idea I want to build a guided todo-app onboarding flow

Silver Bullet routes to idea intake. Product brainstorming clarifies the problem and value. Engineering brainstorming turns it into a milestone seed. GSD milestone creation and discussion lock the first decisions. The workflow then hands off into the next phase of structured planning.

When NOT to use

Do not use silver:brainstorm-idea for:

  • Already-specified work with an existing SPEC.md
  • Implementation, debugging, or bug-fix work
  • Infrastructure, release, or trivial-change tasks
  • Anything that should route to /silver:feature, /silver:bugfix, /silver:devops, /silver:research, /silver:release, or /silver:fast instead

If in doubt, use /silver instead — it will route the request to the correct workflow automatically.
