Overview

/silver classifies intent and routes to a composer skill (silver:feature, silver:ui, …) or a utility skill (silver:spec, silver:validate, …). Composers orchestrate only — they declare which atomic flows run and in what order. Implementation, review, verification, and ship work always flow through SB-owned lifecycle skills.

Active composition state lives in .planning/workflows/<id>.md (Flow Log CSV rows). The retired single-file WORKFLOW.md model is legacy only. SB is the lifecycle authority — no external workflow delegation.

Flow numbers are stable catalog IDs. Post-execution gate order (REVIEW → VERIFY → SECURE) does not always match flow numbering. Runtime order is defined in composer skills and hooks/lib/orchestrator-state.sh.

Composer Workflows

Each composer declares a standard composition chain using FLOW vocabulary. Conditional flows (BOOTSTRAP, CLARIFY, DECIDE, SPECIFY, DEBUG) insert when context signals require them.

ComposerEntry signalsStandard composition chain
/silver:clarify idea, concept, fuzzy requirement, no SPEC.md FLOW 3 (CLARIFY) → handoff to silver:feature / silver:devops / silver:research
/silver:feature add, build, implement, new feature, enhance FLOW 1–5 (conditional) → FLOW 13 (pre-plan) → FLOW 6 → [FLOW 7 if UI] → FLOW 8 → post-execution chain
/silver:bugfix bug, broken, crash, error, regression FLOW 2 (optional) → FLOW 15 (DEBUG) → FLOW 6 → FLOW 8 → post-execution chain
/silver:ui UI, frontend, component, screen, design FLOW 1–6 (conditional) → FLOW 7 → FLOW 8 → FLOW 9 → post-execution chain
/silver:devops infra, CI/CD, terraform, IaC, cloud FLOW 2 → [3–4] → blast-radius + devops-skill-router → FLOW 13 (DevOps) → FLOW 6 → FLOW 8 → post-execution chain
/silver:research compare X vs Y, spike, which technology FLOW 3 → FLOW 4 → [FLOW 5] → handoff to feature/devops or stop
/silver:release release, publish, version, tag v FLOW 13 → FLOW 12 (UAT audit) → FLOW 18 (milestone + gap closure) → FLOW 16–17 → delivery tail → silver:create-release
/silver:fast trivial, typo, bounded small change Tier 1 direct edit; Tier 2 lightweight FLOW 6/8/12 slice; Tier 3 escalate to silver:feature

Utility skills map to atomic flows directly: /silver:spec → FLOW 5 (SPECIFY); /silver:ingest → FLOW 5 sub-step; /silver:validate → gap analysis sub-step in FLOW 5/6/11.

Post-Execution Sequencing

For silver:feature, silver:ui, silver:devops, and silver:bugfix, the mandatory order after FLOW 8 (EXECUTE) is:

  1. FLOW 9 (UI QUALITY) — always for silver:ui; for silver:feature only when UI scope is detected
  2. FLOW 10 (REVIEW) — silver:review-request → silver:review → silver:review-triage
  3. FLOW 12 (VERIFY) — silver:verify + verify-tests
  4. FLOW 11 (SECURE) — security + silver:secure, with silver:validate as needed
  5. FLOW 13 (QUALITY GATE, pre-ship)
  6. FLOW 14 (SHIP) — silver:branch-finish → silver:completion-audit → silver:ship
FLOW 8 EXECUTE → [FLOW 9 UI QUALITY if UI] → FLOW 10 REVIEW → FLOW 12 VERIFY → FLOW 11 SECURE (+ silver:validate as needed) → FLOW 13 QUALITY GATE (pre-ship) → FLOW 14 SHIP

Composition vs Enforcement

Composer skills declare full FLOW 1–18 composition chains (including conditional FLOW 1–5 orientation/clarify/decide atoms). The orchestrator enforcement queue omits optional pre-execution atoms by default — hooks block edits on mandatory pre-execution skill markers only. Parent orchestrators insert skipped flows when context scan flags require them.

Worker templates under templates/orchestrator-workers/ implement one catalog flow each. Per-flow skill steps, produces, and exit conditions live in docs/composable-flows-contracts.md — not in composer SKILL.md files.

Hook Activation & Recommended Tools (v0.47.1)

As of v0.47.1, hooks engage only when a project is SB-initiated: both .silver-bullet.json and silver-bullet.md must exist. Non-initiated workspaces receive no enforcement — run /silver:init first.

Recommended tools (opt-in):

  • Graphify — recommended_tools.graphify.enabled_by_user in .silver-bullet.json; preferred retrieval before planning, editing, review, and release
  • agentmemory — recommended_tools.agentmemory.enabled_by_user; session capture and git-backed memory export. When both are enabled: save via agentmemory, retrieve via Graphify

Consent, install, and enforcement-suspend flows run through /silver:init and /silver:update.
